# Gazprom-hackathon-case3
"Team Ofey" team's repository with solution of case №3 Gazprom AI Automization hackathon. PLC analytic system.

### 1. Общая цель проекта

Мы создаем программный модуль на языке Rust. Его задача — в реальном времени анализировать 20 независимых потоков данных от аналоговых датчиков и для каждого потока определять, является ли текущий сигнал нормальным или аномальным (свидетельствующим об отказе).

Модуль должен работать в очень жестких условиях: на промышленных контроллерах с ограниченной памятью, процессорным временем и без возможности динамически выделять память во время работы.

### 2. Ключевая идея и архитектура

В основе лежит архитектура "Ансамбль из 20 независимых экспертов".

*   "Эксперт" — это одна самостоятельная модель для обнаружения аномалий, основанная на алгоритме Random Cut Forest (RCF).
*   "Ансамбль" — это совокупность из 20 таких экспертов.
*   Принцип работы: Каждый эксперт "закреплен" за своим потоком данных. Когда на 20-миллисекундном цикле приходит новая порция данных (20 точек), i-я точка данных отправляется на обработку к i-му эксперту. Это гарантирует, что контекст (память о предыдущих точках) одного потока никогда не смешивается с контекстом другого.


### Итоговый процесс (по шагам):

1.  Запуск: Приложение стартует. В памяти (на стеке или в static) один раз создается массив из 20 "экспертов". На этом этапе резервируется вся необходимая память (20 * ~256 КБ).
2.  Цикл обработки (каждые 20 мс):
    a. Приходит новый "срез" данных — 20 точек.
    b. С помощью rayon мы запускаем параллельную обработку. Каждый эксперт из нашего массива получает свою точку.
    c. Каждый эксперт независимо от других:
        i. Вычисляет "оценку аномальности" (score) для своей точки на основе своей внутренней "памяти".
        ii. Обновляет свою "память" (update) новой точкой.
    d. Результаты (20 оценок аномальности) собираются.
3.  Завершение: После обработки всех данных результаты записываются в CSV-файлы.
