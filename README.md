# Gazprom-hackathon-case3
"Team Ofey" team's repository with solution of case №3 Gazprom AI Automization hackathon. PLC analytic system.

### 1. Общая цель проекта

Создаётся программный модуль на языке Rust. Его задача — в реальном времени анализировать 20 независимых потоков данных от аналоговых датчиков и для каждого потока определять, является ли текущий сигнал нормальным или аномальным (свидетельствующим об отказе).

Модуль должен работать в ограниченных условиях: на промышленных контроллерах с ограниченной памятью (5 Мб), процессорным временем(20 мс на кластер показаний) и без возможности динамически выделять память во время работы.

### 2. Ключевая идея и архитектура

В основе лежит архитектура "Ансамбль из 20 независимых экспертов".

*   "Эксперт" — это одна самостоятельная модель для обнаружения аномалий, основанная на алгоритме Random Cut Forest (RCF).
*   "Ансамбль" — это совокупность из 20 таких экспертов.
*   Принцип работы: Каждый эксперт "закреплен" за своим потоком данных. Когда на 20-миллисекундном цикле приходит новая порция данных (20 точек), i-я точка данных отправляется на обработку к i-му эксперту. Это гарантирует, что контекст (память о предыдущих точках) одного потока никогда не смешивается с контекстом другого.


### Итоговый процесс (по шагам):

1.  Запуск: В памяти, в static массивах, один раз создается массив из 20 "экспертов". На этом этапе резервируется вся необходимая память (20 * ~256 КБ).
2.  Цикл обработки (каждые 20 мс):
    a. Приходит новый массив данных — 20 точек.
    b. Эксперты последовательно обрабатывают своё показание.
    c. Каждый эксперт независимо от других:
        i. Вычисляет "оценку аномальности" (score) для своей точки на основе своей внутренней памяти.
        ii. Обновляет свою память новой точкой.
    d. Результаты собираются и распределяются по своим csv файлам.
3.  Завершение: После обработки каждого цикла данные записываются в выделенные csv файлы, что позволяет не использовать динамическое выделение памяти.


### Маплист по репозиторию:
В папке bin - toad, готовый бинарный файл, который следует использовать для проверки решения кейса.
В папке input_folder - генерированные датасеты, код для их генерации. Прямого отношения к выполнению кейса не имеет, к проверке не предпологается.
В папке model - файлы формата .rs (Rust программа), являющиеся несобранным решением кейса (исходный код программы).

               РУКОВОДСТВО ПОЛЬЗОВАТЕЛЯ ПРОГРАММЫ TOAD
          (Team Ofey Anomaly Detector, версия 1.0.0)

1. НАЗНАЧЕНИЕ ПРОГРАММЫ
--------------------------------------------------------------------------------
TOAD – это консольная утилита для пакетного детектирования аномалий в данных
многомерных временных рядов. Программа анализирует входной CSV-файл, содержащий
временные метки и показания ровно 20 датчиков, и для каждого датчика формирует
отдельный выходной файл, в котором каждая строка помечена флагом качества:
1 – значение признано нормальным, 0 – обнаружена аномалия.

Алгоритм детектирования реализован во встроенной библиотеке `anomaly_detector`
(ансамблевый метод `Ensemble20`). Программа работает в окружении `no_std`
(не требует стандартной библиотеки Rust) и использует только системные вызовы
POSIX через `libc`, что обеспечивает высокую производительность и минимальный
размер исполняемого файла.

2. ТРЕБОВАНИЯ К ВХОДНОМУ ФАЙЛУ
--------------------------------------------------------------------------------
Программа ожидает один обязательный аргумент командной строки – путь к файлу
в формате CSV со следующими характеристиками:

    * Разделитель полей – точка с запятой (';').
    * Первая строка – заголовок, содержащий имена колонок.
      - Первая колонка может иметь любое имя (обычно "TimeStamp" или "Время").
      - Далее должно следовать 20+ колонок с именами датчиков (может и больше, но они не будут обработаны)
      - Имена датчиков не должны быть пустыми и не должны содержать символов
        '/', '\', '\0', ';' (они будут заменены на '_' при создании файлов).
    * Каждая последующая строка – одна запись временного ряда:
      - Первое поле – временная метка (любая строка, не анализируется,
        копируется в выходные файлы как есть).
      - Следующие 20+ полей – числовые значения типа f32 (допустимы знак минус,
        десятичная точка; разделители тысяч игнорируются). Поля не должны быть
        пустыми.
    * Кодировка файла может быть:
      - UTF-8 (с BOM или без него). BOM в начале файла удаляется автоматически.
      - Windows-1251 (CP1251) – если заголовок не является корректным UTF-8,
        программа считает, что файл в CP1251, и конвертирует имена датчиков
        в UTF-8.
    * Максимальный размер файла – 30 МБ (ограничение буфера чтения).
    * Строки должны заканчиваться символом LF ('\n') или CRLF ('\r\n').
      Одиночные CR ('\r') удаляются при нормализации.

Пример корректного входного файла (UTF-8, BOM отсутствует):

TimeStamp;Temp1;Pressure2;Vibration3;... 
2025-03-15 10:00:00;23.45;1012.3;0.0021;...
2025-03-15 10:00:01;23.47;1012.1;0.0025;...

3. ЗАПУСК ПРОГРАММЫ
--------------------------------------------------------------------------------
Для удобства запуска бинарник следует скопировать в директорию "/usr/local/bin" или другую необходимую.
Следующий синтаксис представлен именно для такого условия.
Синтаксис:

    toad <путь_к_входному_CSV>

Пример:

    toad ./data/sensors_2025-03-15.csv

В случае успешного выполнения программа возвращает код 0 и не выводит никаких
сообщений в стандартный вывод (stdout). Вся диагностика ошибок направляется
в стандартный поток ошибок (stderr).

4. ВЫХОДНЫЕ ДАННЫЕ
--------------------------------------------------------------------------------
При успешной обработке программа создаёт в текущей рабочей директории папку:

    output_folder/

Внутри неё будет создано РОВНО 20 файлов с расширением .csv. Имя каждого файла
формируется из соответствующего имени датчика, взятого из заголовка входного
файла, с заменой недопустимых символов ('/', '\', '\0', ';') на знак
подчёркивания '_'.

Каждый выходной файл имеет кодировку UTF-8 с BOM (EF BB BF) и содержит:

    * Заголовочную строку: TimeStamp;ИмяДатчика;0 - Bad, 1 - Good
    * Строки данных, разделённые точкой с запятой:
        - Временная метка (байты скопированы из исходного файла)
        - Числовое значение с фиксированной точностью 6 знаков после запятой
        - Флаг качества: 1 (норма) или 0 (аномалия)

Пример содержимого файла "output_folder/Temp1.csv":

TimeStamp;Temp1;0 - Bad, 1 - Good
2025-03-15 10:00:00;23.450000;1
2025-03-15 10:00:01;23.470000;1
2025-03-15 10:00:02;27.123456;0
...

5. КОДЫ ВОЗВРАТА (ОШИБКИ)
--------------------------------------------------------------------------------
В случае возникновения ошибки программа немедленно завершается с ненулевым
кодом возврата. Ниже приведена расшифровка кодов:

    1 – Неправильное количество аргументов (аргумент с именем файла не
        передан) или указатель на аргумент нулевой.
    2 – Ошибка при открытии или чтении входного файла (файл не найден,
        нет прав на чтение, размер превышает 30 МБ и т.п.).
    3 – Ошибка при разборе заголовка CSV (например, количество полей данных
        меньше 20, встретилось пустое имя поля, не найдена точка с запятой).
    4 – Внутренняя ошибка: не удалось получить имя датчика по индексу.
    5 – Не удалось создать папку output_folder (например, нет прав на запись
        в текущей директории) или открыть один из выходных файлов.
    6 – Ошибка при записи заголовка в выходной файл (нехватка места на диске,
        разрыв соединения и т.п.).
    7 – Ошибка при записи строки данных в один из выходных файлов.

6. СИСТЕМНЫЕ ТРЕБОВАНИЯ И ОГРАНИЧЕНИЯ
--------------------------------------------------------------------------------
    * Программа скомпилирована для Linux (x86_64 или aarch64) и использует
      системные вызовы через libc. Запуск на других ОС не гарантируется.
    * Для работы необходимы права на чтение входного файла и права на запись
      в текущую директорию (для создания output_folder/ и файлов внутри).
    * Максимальная длина пути к выходному файлу – 255 байт (включая имя папки
      и расширение .csv). Если имя датчика слишком длинное, оно будет обрезано.
    * Программа не использует динамическое выделение памяти в куче (no_std),
      все буферы статические. Это исключает утечки памяти и гарантирует
      предсказуемое потребление ОЗУ (около 30 МБ для буфера CSV).

7. ВОЗМОЖНЫЕ ПРОБЛЕМЫ И ИХ РЕШЕНИЕ
--------------------------------------------------------------------------------
Проблема: "Panic occurred" в stderr.
Причина: Программа завершилась аварийно из-за внутренней ошибки (например,
         повреждение данных). Обратитесь к разработчику с приложением входного
         файла.

Проблема: Код возврата 2, файл не читается.
Решение: Проверьте существование файла и права доступа (команда `ls -l`).
         Убедитесь, что размер файла не превышает 30 МБ.

Проблема: Код возврата 3, заголовок не распознан.
Решение: Убедитесь, что во входном файле не менее 21 колонки (время + 20 данных),
         разделитель – точка с запятой, имена датчиков не пустые. Откройте файл
         в текстовом редакторе и проверьте первую строку.

Проблема: Код возврата 5, не создаётся output_folder или файлы.
Решение: Проверьте наличие свободного места на диске и права на запись
         в текущей папке. Удалите старую папку output_folder, если она была
         создана с ограниченными правами.

Проблема: В именах выходных файлов отображаются знаки вопроса или кракозябры.
Решение: Убедитесь, что терминал/файловый менеджер поддерживает UTF-8.
         Программа записывает имена файлов в UTF-8, поэтому они корректно
         отобразятся в любой современной среде.

8. ПРИМЕР ПОЛНОГО ЦИКЛА РАБОТЫ
--------------------------------------------------------------------------------
Допустим, у нас есть файл `data.csv` со следующим содержимым (CP1251):

Время;Температура;Давление;Вибрация;... (ещё 17 полей)
01.01.2025 00:00:00;22,5;760,0;0,001;...
...

Запускаем программу:

$ toad data.csv

Если ошибок нет, программа завершится с возратом значения 0. Проверяем результат:

$ ls output_folder/
Вибрация.csv  Давление.csv  Температура.csv  ... (ещё 17 файлов)

Просмотрим один из файлов:

$ cat output_folder/Температура.csv
TimeStamp;Температура;0 - Bad, 1 - Good
01.01.2025 00:00:00;22.500000;1
01.01.2025 00:00:01;22.500000;1
01.01.2025 00:00:02;22.510000;1
01.01.2025 00:00:03;30.123456;0   <-- аномалия
